# Status Screens Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task by task.
> Steps use checkbox syntax for tracking.

**Goal:** Show the Bluetooth PIN (only while it is needed) and the radio status on the
T-Echo e-paper and the T-Beam Supreme OLED.

**Architecture:** A portable status record and text layout (with the PIN rule and the
refresh policy) in `mcu/app/rnc_status.{h,c}`, tested on the host. Firmware code fills the
record from the LoRa interface, the RNode module and a new Bluetooth state, and a
low-priority task per board draws the layout with Adafruit GFX (GxEPD2 on the T-Echo,
Adafruit SH110X on the Supreme).

**Tech Stack:** C11 (portable), Arduino/PlatformIO C++, GxEPD2, Adafruit GFX, Adafruit
SH110X, Adafruit BusIO, ctest.

**Spec:** docs/display-status-design.txt (approved 2026-11-14, with section 6.6). Read it first.

## Global Constraints

- The PIN is shown only in Bluetooth states ADVERTISING and CONNECTED; never in OFF or
  SECURE; never when no PIN is set; the record's PIN field is zeroed when not visible.
- No secret on screen other than the PIN (never the Wi-Fi password).
- Layout profiles: OLED 21 columns x 8 rows; e-paper 16 columns x 12 rows. The PIN is on
  its own line and is never dropped; lower-priority lines go first.
- Refresh: OLED at most once a second and only when the layout changed. E-paper: only when
  the layout changed, at least 15 s apart, partial refresh, a full refresh every 5 minutes;
  a change in PIN visibility is drawn at once, at least 2 s after the last refresh.
- The display task runs at priority 1 (below the radio and Reticulum tasks at 2), only
  reads shared state, never writes it; a screen that fails to start ends its task silently.
- Version text is `RNC_MCU_VERSION`.
- Display code and libraries only in `lilygo_t_echo` (RNC_DISPLAY_EPAPER) and
  `lilygo_t_beam_supreme` (RNC_DISPLAY_OLED); library versions pinned exactly (use the
  latest release that resolves at implementation time and record it in platformio.ini).
- T-Echo display pins (SPIM0): CS 30, DC 28, RESET 2, BUSY 3, SCK 31, MOSI 29, no MISO.
  Supreme OLED: SH1106 128x64, address 0x3C, default `Wire` on SDA 17, SCL 18.
- C code compiles with `-Wall -Wextra -Wpedantic -Werror`. Commit messages: no emoji, no
  tool taglines.

## Review Focus

1. The PIN never appears when the link is SECURE, when Bluetooth is OFF, or when no PIN is
   set, including after a state change back and forth (Task 1 tests, Task 3 hardware check).
2. A burst of changes (a packet every second) never refreshes the e-paper more than once per
   15 s, but a PIN visibility change still shows within about 2 s (Task 2 tests).
3. Extreme values never overflow a line: 21 or 16 column limits with long mode text, negative
   and large RSSI/SNR, 10-digit counters, frequency 1020 MHz (Task 1 tests).
4. "No signal yet" until a packet is received; counters and airtime never shown as garbage
   when the radio never started (Task 1 tests).
5. A screen that fails to initialise leaves radio, USB and Bluetooth working (the
   init-failure branch of `rnc_display_step` is tested on the host in Task 2; Tasks 4 and 5
   check on the boards that the radio and Bluetooth still work with the display running).

### Task 1: Status record, layout and PIN rule

**Files:** Create `mcu/app/rnc_status.h`, `mcu/app/rnc_status.c`, `mcu/tests/test_status.c`;
Modify `mcu/CMakeLists.txt` (library `rnc_mcu_app` gets rnc_status.c; `test_mcu_status` next to
`test_mcu_net`), `mcu/tests/mcu_unit.sh` (build and run it), `library.json` (srcFilter).

**Interfaces:**
- Produces (in `rnc_status.h`):
  - `typedef enum { RNC_PHASE_STARTING, RNC_PHASE_SETUP, RNC_PHASE_RUNNING } rnc_status_phase;`
  - `typedef enum { RNC_LINK_NONE, RNC_LINK_USB, RNC_LINK_BLE, RNC_LINK_WIFI } rnc_status_link;`
  - `typedef enum { RNC_BLE_OFF, RNC_BLE_ADVERTISING, RNC_BLE_CONNECTED, RNC_BLE_SECURE } rnc_ble_state_t;`
  - `typedef struct rnc_status { rnc_status_phase phase; char mode[24]; int radio_on; int radio_set;
    uint32_t freq_hz, bw_hz; uint8_t sf, cr; int8_t txp_dbm; int has_signal; int16_t rssi_dbm;
    int16_t snr_quarter_db; uint32_t rx_packets, tx_packets; uint16_t airtime_permille;
    rnc_status_link link; rnc_ble_state_t ble; char pin[7]; char version[12]; } rnc_status;`
  - `int rnc_status_pin_visible(rnc_ble_state_t ble, int pin_set)`
  - `typedef struct rnc_status_profile { unsigned cols, rows; } rnc_status_profile;` with
    constants `RNC_PROFILE_OLED` (21, 8) and `RNC_PROFILE_EPAPER` (16, 12)
  - `#define RNC_STATUS_MAX_COLS 21`, `#define RNC_STATUS_MAX_ROWS 12`
  - `unsigned rnc_status_layout(const rnc_status *s, rnc_status_profile p,
    char lines[RNC_STATUS_MAX_ROWS][RNC_STATUS_MAX_COLS + 1])` returns the rows used, every
    row NUL terminated and at most `p.cols` characters.

  `extremes`: 10-digit counters, 1020 MHz, rssi -157 and 0, snr -128 and 127, a 23 character

### Task 2: Refresh policy

**Files:** Modify `mcu/app/rnc_status.h`, `mcu/app/rnc_status.c`, `mcu/tests/test_status.c`

**Interfaces:**
- Produces: `typedef struct rnc_refresh { unsigned min_interval_ms, pin_interval_ms,
  full_interval_ms; uint64_t last_ms, last_full_ms; int last_pin_visible; int drawn_once; }
  rnc_refresh;`
  `typedef enum { RNC_REFRESH_NONE, RNC_REFRESH_PARTIAL, RNC_REFRESH_FULL } rnc_refresh_action;`
  `void rnc_refresh_init(rnc_refresh *r, unsigned min_ms, unsigned pin_ms, unsigned full_ms)`
  `rnc_refresh_action rnc_refresh_decide(rnc_refresh *r, int layout_changed, int pin_visible,
  uint64_t now_ms)` (records the draw when it returns a non-NONE action).
  OLED init is (1000, 1000, 0) (full interval 0 = never a full refresh); e-paper is
  (15000, 2000, 300000).
  `typedef struct rnc_display_state { char prev[RNC_STATUS_MAX_ROWS][RNC_STATUS_MAX_COLS + 1];
  unsigned prev_rows; } rnc_display_state;`
  `rnc_refresh_action rnc_display_step(rnc_refresh *r, rnc_display_state *st, const rnc_status *s,
  rnc_status_profile p, int init_ok, uint64_t now_ms, char out[RNC_STATUS_MAX_ROWS][RNC_STATUS_MAX_COLS + 1],
  unsigned *rows)`: lays the status out, compares it with `st->prev`, asks `rnc_refresh_decide`
  (with `pin_visible` taken from whether `s->pin[0]` is set), and returns the action; with
  `init_ok` 0 it always returns NONE. On an action other than NONE it fills `out` and `*rows`
  and updates `st->prev`. This is what the display task calls, so the task's logic is tested on
  the host.

- [ ] Step 1: tests `first_draw_is_full`, `no_change_no_draw`, `change_waits_min_interval`
  (changes at t=0, 5 s, 14 s: draws at 0 and at 15 s only), `pin_change_is_prompt`
  (a PIN visibility change 3 s after a draw draws within `pin_interval_ms`, a plain change at
  the same time does not), `full_refresh_every_five_minutes` (a changed layout after 300 s is
  FULL), `burst_rate` (a change every second for 10 minutes gives at most 41 draws with the
  e-paper values; Review Focus 2), and for `rnc_display_step`: `init_failed_never_draws`
  (`init_ok` 0 returns NONE for every input), `unchanged_layout_is_quiet`, `fills_out_on_draw`
  (the returned rows equal `rnc_status_layout`'s).
- [ ] Step 2: run; Expected: FAIL (symbols missing). Step 3: implement. Step 4: run the unit
  tests; Expected: PASS. Commit `app: refresh policy and display step for the screens`.

### Task 3: Bluetooth state, status filler and display task skeleton

**Files:** Modify `mcu/platformio/src/ble_mode.h`, `ble_nrf.cpp`, `ble_esp32.cpp`,
`mcu/platformio/src/main.cpp`, `mcu/platformio/src/wifi_mode.h` (phase hook only if needed);
Create `mcu/platformio/src/status_fill.h`, `status_fill.cpp`, `display_mode.h`,
`display_task.cpp`.

**Interfaces:**
- Consumes: Task 1 record and layout, Task 2 policy.
- Produces:
  - `rnc_ble_state_t rnc_ble_state(void)` in `ble_mode.h` (stub returning `RNC_BLE_OFF` where
    there is no Bluetooth). nRF: OFF until `rnc_ble_start` succeeded, then ADVERTISING when
    `Bluefruit.connected()` is 0, CONNECTED when connected and
    `Bluefruit.Connection(0)->secured()` is false, SECURE when secured. ESP32: OFF, then
    ADVERTISING / CONNECTED / SECURE from `g_connected` and `g_secure`.
  - `void rnc_status_sources(const rnc_lora_if *li, const rnc_rnode *rn, const rnc_mcu_cfg *cfg)`
    (stores pointers; the cfg is copied once), `void rnc_status_set_phase(rnc_status_phase)`,
    `void rnc_status_set_link(rnc_status_link)`, `void rnc_status_fill(rnc_status *out, uint64_t now_ms)`.
    `rnc_status_fill` fills the mode text (`RNode`, or `USB` / `WiFi` followed by the LoRa mode
    when it is not off), the radio state and settings (from the RNode module in rnode mode,
    from the configuration otherwise), RSSI/SNR/counters from `li->stats`, airtime permille
    from `rnc_airtime_used(&li->budget, now_ms)` over `li->budget.budget_ms`, the Bluetooth
    state, the PIN digits only when `rnc_status_pin_visible()` says so (zeroed otherwise) and
    `RNC_MCU_VERSION`. It reads only.
  - `bool rnc_display_start(void)` in `display_mode.h` creates the display task (priority 1);
    returns false when no display is built in. The driver functions (Tasks 4 and 5) are
    `bool display_init(void)` and `void display_draw(const char lines[][22], unsigned rows,
    rnc_refresh_action action)`, with a profile constant `DISPLAY_PROFILE`.

- [ ] Step 1: build all 8 environments with the new code and no display flag
  (`mcu/build-platformio.sh`, output in the scratchpad); Expected: all build, the six
  without a screen within a few hundred bytes of the previous size.
- [ ] Step 2: implement `rnc_ble_state()` on both stacks and the stubs; build the nRF and ESP32
  environments; Expected: PASS.
- [ ] Step 3: implement `status_fill.*` and `display_task.cpp` (the task loop: every 200 ms
  fill, layout, `rnc_refresh_decide` against a copy of the previous lines, draw); in `main.cpp`
  call `rnc_status_sources`, `rnc_status_set_phase` (STARTING at the top of `setup()`, SETUP
  just before `rnc_provision_console`, RUNNING before the tasks start) and `rnc_display_start()`
  early in `setup()` (before the provisioning window).
- [ ] Step 4: the task loop is only I/O around `rnc_display_step` (Task 2, already tested,
  including the init-failure case of Review Focus 5): every 200 ms `rnc_status_fill`, then
  `rnc_display_step`, then `display_draw` when the action is not NONE; if `display_init()`
  returned false the task calls `rnc_display_step` with `init_ok` 0 once and exits.
- [ ] Step 5: build all 8 environments again; run the unit tests. Commit
  `firmware: Bluetooth state, status filler and display task skeleton`.
